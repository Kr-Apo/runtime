# Bounded Pixi weighted-mesh pilot (R2)

Experimental local bench only. Not exported from npm, not an extension of the old Replay/Pixi API, and not a general browser/game Physics guarantee. Numeric base: N6 fd38ae4; native author/export reference: Editor E1 18bfafaf. No old mode/core/format/Phaser changes.

## Data and ownership

`createBoundedBench(trustedConfig)` owns the unchanged N6 supervisor and a separate graphics Chrome process. `create(approvedId, history, instanceId, placement)` accepts only the six exact Simple/Mixed N6 qualifications. It creates its own N6 authorization/session and binds a graphics-only view; no caller-supplied consumer, simulation provider or free solver is accepted. The returned numeric facade is the existing closed N6 API. Only detached accepted snapshots cross to the graphics page. The page has no numerical authority, ticket, consumer or channel back into the numeric environment.

The lower-level `host.mjs` and `graphics.mjs` are qualification tooling, including diagnostics and explicit fault tests; they are not independent admission APIs. `BoundedPixiView` is only a graphics builder under that trusted launcher. It cannot authenticate a malicious owner of its own page/code, and its ordinary snapshot validation must never replace N6 admission.

The view reads named E1 influence locals directly. For each vertex: sum `weight * worldBone * influenceLocal` in native order, divide by the positive sum; empty/all-zero rows use the native host-bone point. No epsilon pruning, four-term cap, inverse-bind reconstruction, coordinate repair, FK, evaluate, clock or Physics call. Keep JSON-derived bind coordinates in double precision until the final Float32 draw buffer. Convert world Y-up to Pixi Y-down once. Native JSON/weights/UVs/triangles remain immutable.

Reuse unchanged `MeshAtlas`, `regionQuad`, and `DarkTint` at dark=0 from the current runtime. MeshAtlas static UV-domain cropping is atlas/trim support, not a Clipping attachment. Its module indirectly imports numerical class definitions via the core index; dedicated CDP precise coverage proves that their constructors/evaluate are not called by graphics. The renderer never uses MeshBinding's FFD/setup-evaluator path.

## Scope and failures

One fixed default skin, Physics-only N6 bone clips, static regions and weighted/unweighted meshes, Normal blend. Reject FFD, linked meshes, clipping attachments, dynamic skins, mixing, extra constraints, dark tint, sequences, and nonempty slot/draw-order/event timelines. This does not change the support of those features in old runtime modes. Only the exact six approved native fixtures were graphically qualified here; no blanket arbitrary-mesh validator claim.

`view.present()` in the Node bridge fetches its own N6 session's current accepted state. `view.preview()` fetches only the N6-qualified pure preview while state is seek_preview; the completed Physics tick is retained separately from preview.tick. No arbitrary seeks, truncation, host time, implicit pumps/resets or extension beyond H720/H19. Disposal is terminal. Numerical faults close N6 continuation and do not publish the rejected candidate. A healthy graphics retry reuses the same accepted numeric snapshot, never advances Physics.

Each graphics view owns two mesh/buffer banks and two full-size RenderTextures. Pages are borrowed from the private graphics asset owner; mutable geometry is never shared between actors. Validate resources/finite data before preparation, draw the back target, then switch the published texture only on success. Clear every transparent target/canvas to RGBA zero: nonzero RGB with alpha zero is invalid for PMA composition. A preparation/back-target error preserves the previous front. Final composition/driver/context failures are not universally GPU-atomic; context loss destroys physical pixels and needs an explicit redraw from an accepted snapshot after restoration.

Destroy views before their asset/context owner. The launcher explicitly disposes pages/app, then closes graphics and N6 contexts. The GL instrumentation records logical create/delete/loss events, not physical VRAM. Shared program-cache handles can remain in its ledger until context loss notification/termination; they are not silently claimed as explicit deletes. Fixed repeated cycles must stabilize, and no owned buffers/targets survive normal view destruction.

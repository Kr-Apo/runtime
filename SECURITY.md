# Security policy

This experimental alpha has no guaranteed security-support window or response
time. Use trusted local assets and keep independent backups. The public loader
is not an adversarial-input resource sandbox or an origin firewall.

Do not disclose exploitable vulnerabilities, private projects or secrets in a
public issue. Use GitHub's **Security > Report a vulnerability** when private
vulnerability reporting is enabled. If that control is unavailable, do not post
sensitive details publicly; ask the maintainers to enable a private reporting
channel without attaching the report. No email address or external support
service is designated by this policy.

Include the exact release/commit, affected component, environment, impact and a
minimal original reproduction you may share. Redact credentials and personal
paths. Do not test on other people's services or projects. Coordinate disclosure
privately before publication. There is no automatic telemetry or report upload
in the supplied demo.

The Windows executables are unsigned. Check the release checksum, obtain files
from the verified project release and follow your system's security decisions.
Do not bypass warnings on untrusted files. The bundled launcher is a local static
server, not a production hosting service.

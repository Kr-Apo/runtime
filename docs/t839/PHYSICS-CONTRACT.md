# T839 — Native Physics and qualification boundary

Local development from Runtime `11128ed84991af5200707a9ddc586fc565f89a58` and
Editor `0063d784f80d0f51814ba0e742fe8fcacc864911`. No version/npm/release change.

Native Rust PhysicsConstraint.bone is serialized through the author schema and
native template as `target: "driven bone", bones: []`. This is the simulated bone,
not IK/Transform's separate control target. Previously TS only read bones[0] and
never activated that real native export.

`core/src/rig.ts::physicsBone` now resolves references for parsing and stateful
evaluation without changing data or the integrator:

| target | bones | Contract |
|---|---|---|
| existing bone | [] | canonical native driven bone |
| empty string | one existing bone | historical bones-only form |
| existing bone | same single bone | redundant, unambiguous form |
| missing/unknown, conflicting references or multiple bones | any | RigFormatError, never a default bone guess |

Existing valid v1/v2 forms remain readable. Previously tolerated contradictory or
malformed inputs now fail loudly. Fields, independent axes, FFD and texture data
retain meaning; no migration. Without EvaluationState, evaluate still applies no
physics. The separate optional author-file reader is not this exported JSON API.

**Activation is not trajectory parity.** Nominal step 1/120 is shared, but caps
are Rust8/TS32, remainder is shared/per-bone, numbers f32/double, and transport
policies differ. PixiJS still rejects constraints. Phaser retains an explicit
qualification warning. CPU exports still refuse physics. Editor preflight code
becomes `runtime-physics-unqualified` and still requires consent, warning that
readers before T839 ignore native target-only physics. No route is unlocked.

## Authentic fixtures and reproduction

`core/test/fixtures/t839/{single,multiple,parent}.native.json` are exact bytes
generated by Editor `export/tests/t839_physics.rs`: author load, native conversion,
shipped preset. These numerical rigs have no textures; they are not visual demos.
Negative/legacy tests alter in-memory copies explicitly, never historical files.

In the companion Editor, set T839_FIXTURE_DIR to a **nonexistent** evidence folder
and run `cargo test --locked -p ankhimate-export --test t839_physics`. It emits
author JSON, native JSON and controlled Rust references. Rerun refuses to overwrite
the folder. Unset the variable before whole-workspace tests. In Runtime after build:

```
node scripts/t839-physics-reference.mjs <new-evidence-folder>
```

The script checks native-byte equality, reset deterministic replay and finite
components. It asserts bounded single-constraint 60Hz parity, explicitly reports
all 12 sequences, and never labels known mismatches as PASS. Max world-component
error at 60Hz for transformed parent: .000004160; single144Hz .052767,
multiple144Hz .314059, single half-second hitch 2.233918. Six new core tests cover
references/v1/v2/state/transport. The existing Pixi refusal test supplies a valid
reference now to reach the same adapter gate rather than fail earlier in parsing.

## Audit conclusions, no further implementation

- Physics replay synchronization requires its own cadence/state contract, not
  simply changing a cap.
- Animated PathPosition export remains refused. A future version/capability must
  make old readers reject unsupported tracks, not silently ignore them. First
  align static path exact-corner and skin resolution.
- Genuine native draw-order pose probe at weights .4/.6: Rust c,b,a versus TS
  c,a,b. Open P1; mixing remains unchanged.
- Colors/FFD use sequential blending; transforms offset/multiplicative scale;
  discrete tracks highest alpha/later tie. No general layer/mask engine added.
- Interrupted fades can jump. Incoming-only events use (from,to], skipping t=0.

The companion Editor `docs/t839/` contains T839-REPORT.md, compatibility matrix,
PathPosition proposal and next missions. Existing WebGL125 was rerun with identical
baseline/final buffers on one Windows/Chrome/NVIDIA machine. It does not qualify
Physics, paths, broad hardware or physical GUI interaction. Stop for review.
